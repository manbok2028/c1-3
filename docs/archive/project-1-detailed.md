# 체납관리 노코드 자동화 설계 및 구현

## 1\. 프로젝트 목적

본 프로젝트는 체납상담 업무에서 반복적으로 발생하는 신규 접수 확인, 긴급도 분류, 이메일 발송 및 처리상태 기록 업무를 노코드 자동화 도구로 구현하는 것을 목적으로 한다.

기존에는 담당자가 Google Sheets에 입력된 신규 체납상담 자료를 직접 확인하고, 사건의 긴급도를 구분하여 이메일을 발송한 후 처리상태를 다시 입력해야 했다. 이러한 수작업은 시간이 소요될 뿐만 아니라 이메일 발송이나 처리상태 기록이 누락될 가능성이 있었다.

이를 개선하기 위해 다음과 같은 자동화 흐름을 설계하였다.

```text
신규 체납상담 접수
→ Google Sheets 신규 행 저장
→ 긴급사건과 일반사건 자동 분류
→ 고객 또는 담당자에게 이메일 발송
→ Google Sheets 처리상태 자동 업데이트
```

동일한 업무를 Make와 Zapier에서 각각 구현하고, 두 도구의 설정 방식, 조건 분기, 자동 실행, 실행 결과 확인 방법 및 업무 적합성을 비교하였다.

전체 체납관리 업무는 다음 단계로 확장할 수 있도록 설계하였다.

```text
고객 접수 → 운영자 분류 → 담당자 배정 → 고객 상담 → 사건 종결
```

사건의 세무적 판단과 실제 상담은 사람이 수행하고, 반복적인 분류·알림·기록 업무는 자동화하는 것을 기본 원칙으로 하였다.

## 2\. Google Sheets 데이터 구조

자동화에 필요한 접수자료는 Google Sheets의 `체납관리\\\\\\\\\\\\\\\_자동화\\\\\\\\\\\\\\\_실습` 스프레드시트 내 `접수관리` 시트에서 관리하였다.

### 2.1 데이터 항목

|열|항목|주요 내용|
|-|-|-|
|A|접수번호|사건별 고유 접수번호|
|B|접수일시|상담이 접수된 날짜와 시간|
|C|고객명|체납상담 신청 고객명|
|D|고객이메일|자동 이메일 수신주소|
|E|체납기관|국세청·지방자치단체 등|
|F|체납유형|국세·지방세 등 체납 종류|
|G|체납금액구간|체납금액을 일정 기준으로 분류|
|H|압류·공매 여부|압류 또는 공매 진행 여부|
|I|긴급도|긴급사건과 일반사건 구분|
|J|상담내용|고객이 입력한 상담 요청사항|
|K|처리상태|자동화 처리결과 기록|
|L|알림일시|이메일 발송일시|
|M|오류내용|자동화 실패 시 오류내용 기록|

### 2.2 주요 입력값

I열 긴급도에는 `긴급`, `일반` 드롭다운 항목을 설정하였다. H열 압류·공매 여부에도 드롭다운을 설정하여 입력값을 표준화하였다.

K열 처리상태에는 자동화 실행 결과에 따라 다음과 같은 문구가 기록되도록 구성하였다.

* 긴급접수 알림완료
* 일반접수 알림완료
* 처리 중
* 상담종결
* 실패 또는 오류발생

자동화가 값을 입력하는 처리상태 K열과 수식이 적용되는 열은 사용자가 실수로 변경하지 않도록 데이터 보호 기능을 적용하였다.

## 3\. Make 자동화 구현

Make에서는 Google Sheets에 신규 접수자료가 입력되면 이를 자동으로 감지하고, 긴급사건과 일반사건으로 분류하여 이메일을 발송한 후 처리상태를 업데이트하도록 시나리오를 구성하였다.

### 3.1 시나리오 구성

시나리오명은 `프로젝트1\\\\\\\\\\\\\\\_체납접수\\\\\\\\\\\\\\\_긴급일반분류`이며, 전체 흐름은 다음과 같다.

```text
Google Sheets – Watch New Rows
→ Router
→ 긴급경로 또는 일반경로
→ Gmail – Send an Email
→ Google Sheets – Update a Row 또는 Update a Cell
```

!\[Make 전체 워크플로우](01\_Make/make\_전체워크플로우.png)

### 3.2 신규 행 감지

첫 번째 Trigger는 Google Sheets의 `Watch New Rows`이다.

* Spreadsheet: 체납관리\_자동화\_실습
* Sheet: 접수관리
* Table contains headers: Yes
* 감지대상: 새로 추가되는 행
* 시작 위치: 전체 자료 또는 특정 행 이후
* 한 번에 가져올 행 수: 1

Google Sheets에 새로운 자료가 추가되면 해당 행의 접수정보가 Make로 전달된다.

!\[Make 신규 행 감지 성공](01\_Make/make\_watchnewrows\_실행성공.png)

### 3.3 Router와 Filter

Watch New Rows 다음에 Router를 배치하고 `긴급경로`와 `일반경로`를 만들었다. 각 경로에는 다음 Filter를 적용하였다.

```text
긴급경로: 긴급도 = 긴급
일반경로: 긴급도 = 일반
```

!\[Make 긴급경로 실행 성공](01\_Make/make\_긴급경로\_실행성공.png)

### 3.4 이메일 발송 및 처리상태 업데이트

각 경로에 Gmail의 `Send an Email` 모듈을 연결하였다. 긴급경로에서는 긴급사건임을 바로 확인할 수 있는 제목과 내용을 사용하고, 일반경로에서는 상담 접수 안내 이메일을 발송하도록 하였다.

이메일 발송 후 Google Sheets의 해당 행을 찾아 K열 처리상태를 다음과 같이 업데이트하였다.

* 긴급사건: `긴급접수 알림완료`
* 일반사건: `일반접수 알림완료`

!\[Make 자동실행 시트 결과](01\_Make/make\_자동실행\_시트결과.png)

!\[Make 자동실행 이메일 결과](01\_Make/make\_자동실행\_이메일결과.png)

### 3.5 자동실행 확인

수동 `Run once` 테스트를 완료한 후 시나리오를 활성화하였다. Google Sheets에 새로운 자료를 입력하고 Make의 History에서 각 모듈이 순서대로 자동 실행된 것을 확인하였다.

!\[Make History 자동실행 성공](01\_Make/make\_history\_자동실행성공.png)

## 4\. Zapier 자동화 구현

Zapier에서도 Make와 동일하게 Google Sheets 신규 접수 감지, 긴급·일반 분기, 이메일 발송 및 처리상태 업데이트 자동화를 구현하였다.

### 4.1 전체 흐름

```text
Google Sheets – New Spreadsheet Row
→ Paths by Zapier
→ 일반경로 또는 긴급경로
→ Gmail – Send Email
→ Google Sheets – Update Spreadsheet Row
```

!\[Zapier 전체 워크플로우](02\_Zapier/01\_Zapier\_전체워크플로우.png)

### 4.2 Trigger

Google Sheets의 `New Spreadsheet Row`를 Trigger로 설정하였다. `체납관리\\\\\\\\\\\\\\\_자동화\\\\\\\\\\\\\\\_실습` 스프레드시트의 `접수관리` 시트에 신규 행이 추가되면 Zap이 시작된다.

### 4.3 Paths 조건 분기

`Paths by Zapier`를 이용하여 일반사건과 긴급사건 경로를 만들었다.

* 일반경로: 긴급도 값이 `일반`과 정확히 일치
* 긴급경로: 긴급도 값이 `긴급`과 정확히 일치

!\[Zapier 일반경로 실행 상세](02\_Zapier/07\_Zapier\_일반경로\_실행상세.png)

!\[Zapier 긴급경로 실행 상세](02\_Zapier/08\_Zapier\_긴급경로\_실행상세.png)

### 4.4 Gmail 데이터 연결

Gmail에는 Google Sheets에서 가져온 다음 항목을 연결하였다.

* 접수번호: A열
* 고객명: C열
* 고객이메일: D열
* 체납기관: E열
* 체납유형: F열
* 긴급도: I열
* 상담내용: J열

### 4.5 처리상태 업데이트

이메일 발송 후 `Update Spreadsheet Row`를 실행하여 K열 처리상태를 변경하였다. Trigger에서 전달된 `Row ID` 또는 `Row Number`를 연결하여 신규 접수자료가 있는 정확한 행을 업데이트하도록 설정하였다.

### 4.6 Publish 및 자동실행

각 단계의 테스트를 완료한 후 Zap을 Publish하여 활성화하였다. Google Sheets에 신규 행을 입력했을 때 Zap이 자동 실행되는 것을 Zap History에서 확인하였다.

!\[Zapier History 자동실행 성공](02\_Zapier/06\_Zapier\_History\_자동실행성공.png)

## 5\. 긴급·일반 분기 조건

Make와 Zapier 모두 Google Sheets I열의 `긴급도`를 분기 기준으로 사용하였다.

|구분|조건|실행 내용|
|-|-|-|
|일반경로|긴급도 = 일반|일반 이메일 발송 및 일반 처리상태 입력|
|긴급경로|긴급도 = 긴급|긴급 이메일 발송 및 긴급 처리상태 입력|

일반사건과 긴급사건 테스트자료를 각각 입력하여 두 경로가 실제로 한 번 이상 실행되는 것을 확인하였다.

## 8\. 문제와 해결 과정

### 8.1 Make Spreadsheet ID 오류

* 문제: Watch New Rows에서 스프레드시트를 불러오지 못했다.
* 원인: Spreadsheet ID 또는 대상 시트가 정확하게 지정되지 않았다.
* 해결: Google Sheets 주소에서 Spreadsheet ID를 다시 확인하고 `접수관리` 시트를 연결하였다.

### 8.2 Make 시작 위치 설정 문제

* 문제: 테스트자료가 감지되지 않았다.
* 원인: `Choose where to start`의 시작 위치가 맞지 않았다.
* 해결: 전체 자료 또는 특정 행 이후부터 감지하도록 다시 설정한 후 신규 행을 입력하였다.

### 8.3 Make 자동실행 문제

* 문제: `Run once`에서는 실행되지만 자동으로 실행되지 않았다.
* 원인: 시나리오의 스케줄 또는 활성화 설정이 완료되지 않았다.
* 해결: 시나리오 스케줄을 설정하고 활성화한 후 History에서 자동실행 성공을 확인하였다.

### 8.4 Zapier Row 항목 문제

* 문제: Update Spreadsheet Row의 Row 항목에 고정된 숫자 `10`이 표시되었다.
* 원인: Trigger에서 가져온 동적 행 번호가 아니라 테스트 당시의 고정 행 번호가 연결되었다.
* 해결: Trigger의 `Row ID` 또는 `Row Number`를 Row 항목에 다시 연결하였다.

### 8.5 Zapier 처리상태 공란 문제

* 문제: 이메일은 발송되었지만 K열 처리상태가 비어 있었다.
* 원인: 업데이트할 행 또는 K열 입력값이 정확하게 연결되지 않았다.
* 해결: Trigger의 Row ID와 처리상태 입력값을 다시 연결한 후 재시험하였다.

### 8.6 Zapier Publish 문제

* 문제: 단계별 테스트는 성공했으나 신규 행 입력 시 자동 실행되지 않았다.
* 원인: Zap이 초안상태이거나 Publish되지 않았다.
* 해결: 모든 단계를 테스트한 후 Zap을 Publish하고 활성화하였다.

### 8.7 이메일 필드 연결 문제

* 문제: 이메일에 일부 접수정보가 표시되지 않았다.

* 해결: 접수번호, 고객명, 체납기관, 체납유형, 긴급도 및 상담내용을 각각 다시 매핑하였다.

## 9\. Make와 Zapier 비교 분석

|비교 항목|Make|Zapier|
|-|-|-|
|화면 구성|시각적인 모듈 연결 방식|단계별 목록 방식|
|초기 설정|다소 복잡함|비교적 직관적임|
|조건 분기|Router와 Filter 사용|Paths 사용|
|복잡한 흐름|전체 구조 확인이 쉬움|경로별 단계 확인이 쉬움|
|데이터 연결|세밀한 데이터 매핑 가능|필드 선택이 간편함|
|실행기록|History에서 모듈별 확인|Zap History에서 Step별 확인|
|오류 분석|오류 모듈을 시각적으로 확인|실패한 Step 중심으로 확인|
|행 업데이트|행과 열을 세밀하게 지정|Row ID 연결이 중요|
|초보자 편의성|일정한 학습이 필요|상대적으로 접근하기 쉬움|
|적합한 업무|복잡한 분기와 상태관리|단순하고 신속한 앱 연결|

### 9.1 종합평가

Make는 전체 워크플로우를 한 화면에서 확인할 수 있고, Router와 Filter를 이용하여 복잡한 분기를 구성하는 데 유리하였다. 체납관리와 같이 여러 처리상태를 관리하는 업무로 확장하기에 적합하였다.

Zapier는 Trigger, Paths, Gmail, Google Sheets 업데이트가 순서대로 표시되어 설정과정이 비교적 직관적이었다. 다만 처리상태를 정확한 행에 기록하려면 Trigger의 Row ID를 올바르게 연결해야 했다.

단순한 신규 접수 알림에는 Zapier가 편리하지만, 향후 담당자 배정, 자료보완, 상담종결 등 여러 상태와 경로를 관리하려면 Make가 더 적합하다고 판단하였다.

## 11\. 최종 결론

본 프로젝트에서는 체납상담 업무에서 반복적으로 발생하는 신규 접수 확인, 긴급도 분류, 이메일 발송 및 처리상태 기록 업무를 Make와 Zapier를 이용하여 자동화하였다.

Google Sheets의 `접수관리` 시트에 새로운 상담자료가 입력되면 Make와 Zapier가 신규 행을 감지하고, I열 긴급도 값에 따라 일반사건과 긴급사건으로 분류하도록 하였다. 분기 후에는 접수정보가 포함된 Gmail 이메일을 발송하고, 이메일 발송이 완료되면 Google Sheets K열의 처리상태를 자동으로 업데이트하도록 구현하였다.

Make에서는 Watch New Rows, Router, Filter, Gmail 및 Google Sheets 업데이트 모듈을 연결하였다. Zapier에서는 New Spreadsheet Row, Paths, Gmail 및 Update Spreadsheet Row를 연결하여 동일한 업무 흐름을 구현하였다.

일반사건과 긴급사건을 각각 입력하여 두 분기 경로가 실제로 실행되는지 테스트하였다. Make와 Zapier 모두 이메일이 정상적으로 발송되었고, Google Sheets의 처리상태도 해당 사건에 맞게 변경되었다.

구현 과정에서는 Spreadsheet ID 연결, Make의 시작 위치와 자동실행 설정, Zapier의 Row ID 연결, 처리상태 공란 및 Publish 문제 등이 발생하였다. 각 문제의 원인을 확인하고 설정값을 수정하면서 Trigger, Action, Router, Filter, Paths 및 동적 데이터 매핑의 작동 원리를 이해할 수 있었다.

비교 결과, Zapier는 단계별 설정이 직관적이어서 단순한 자동화를 빠르게 구현하는 데 적합하였다. Make는 초기 설정에 다소 학습이 필요하지만, 전체 흐름을 시각적으로 확인할 수 있고 복잡한 조건 분기와 다단계 상태관리로 확장하는 데 유리하였다.

따라서 단순한 신규접수 분류와 이메일 발송에는 Zapier가 편리하지만, 접수·분류·담당자 배정·자료보완·상담·종결 등 복잡한 체납관리 업무를 확장하여 운영하려면 Make가 더 적합하다고 판단하였다.

이번 프로젝트를 통해 동일한 업무를 서로 다른 두 개의 노코드 자동화 도구로 실제 구현하고, 일반·긴급 분기 경로가 각각 자동 실행되는 결과를 확인하였다. 향후에는 중복발송 방지, 실패 알림, 오류내용 기록, 재시도 경로 및 AI 상담내용 요약 기능을 추가하여 더욱 안정적인 체납관리 자동화 시스템으로 발전시킬 수 있다.
